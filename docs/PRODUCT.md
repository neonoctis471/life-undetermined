# 一、项目创作思路

## 1.1 从「给建议」到「让你先走一遍」

「毕业后该找工作还是考研」「要不要回家」「自媒体能做吗」，是知乎上最密集的一类提问。

这类问题的真实困难**不是缺少建议**——建议太多了——而是三件事：

| 真实困难 | 作品里的机制 |
|---|---|
| **建议是别人的语境。** 回答者的家庭、专业、经济条件和你不一样，结论却常被当成通用答案。 | 每张知乎卡片强制写出「**与你不同**」，直接点破不能照搬的地方。 |
| **代价是看不见的。** 你读得到「我选了 A，现在挺好」，读不到「选 A 的那五年里，B 那边会发生什么」。 | 每个结果同时写下**收获、代价、仍然没有答案的部分**；并且你可以真的去走 B 那条线。 |
| **没有人能真的重来一次。** 而「如果当时……」恰恰是这件事上最强的情绪。 | 三次决定**每一次都能回去**，换一个选择重新推演到第五年。 |

所以这不是一个「测测你适合什么职业」的测评，也不是一个建议聚合器。它是一次**具体的、有代价的、可以重来一次的经历**。

## 1.2 叙事结构

```
序章 · 毕业那天
   勾选打算 → 勾选你真正看重的 → 写下自己的话
   同屏呈现：真实毕业调查数据 + 知乎过来人的建议
   ↓
三次选择 · 第 8 天 → 第 7 个月 → 第 4 年
   两种可能 → 具体情境（可查知乎经验） → 你准备怎么办 → 后来
   ↓
五年以后 · 同学聚会
   「你现在平时都在做什么？」+ 五年时间线 + 五年前你自己写的那段话
   ↓
回溯 · 三次决定里，回到任意一次
   ↓
两段人生 · 并排对照
```

每一幕的「情境」都不是抽象的人生岔路，而是一个具体的下午：

> 午餐高峰刚结束，老顾客张叔带着新开的水果店名片来找你，说听说你在学拍摄，问能不能帮他录一段短视频宣传。他希望你本周内完成……你的家人对此感到新奇，但也提醒你本周是旺季。

## 1.3 结果分成两层

- **现在真正发生了（硬状态）**——既成事实，写进权威状态，不可撤销，后续推演必须建立在它之上。
- **这件事，在你身上留下了什么（软状态）**——处理事情的方式、新的视角、对自己的了解、人际与沟通、现实经验、资源与机会、付出的代价、暴露出的问题、第一次。每一条都必须能追溯到上面的具体事实。

第二层有严格约束：**不写鸡汤**（有明确的禁用表达清单）、**不总结「你是一个怎样的人」**、区分**当下 / 持续 / 可能**三种时间尺度，「可能」那一档必须用概率表达并在界面上弱化呈现——因为它还没发生。

一条真实输出：

> **处理事情的方式 · 持续**
> 这是你第一次主动与家人协商工作分配，*而不是*默默承担全部或回避。
>
> **新的视角 · 可能**
> *你以后遇到家庭和个人目标冲突时，也许更愿意提前协商分工。*

## 1.4 刻意不做的事

- **没有分数、等级、徽章、经验条、成就解锁。** 一旦引入分数，「哪条路更好」就有了答案，而这个作品的全部主张是它没有标准答案。
- **等待是设计对象，不是缺陷。** 五年加速最短 5 秒、回溯最短 7 秒，不做成加载转圈，也不缩短——时间流逝需要被感觉到。
- **不编造数据。** 见 2.6。
- **不做排行榜、不做云存档、不做社交裂变。** 与作品立意无关的增长机制一律不加。

# 二、适配知乎社区的场景价值

**这是本作品的核心，不是装饰功能。**

## 2.1 场景本身就长在知乎上

毕业方向选择（考研 / 考公考编 / 就业 / 跨专业 / 留学 / 回家发展 / 自由职业 / 做自媒体 / Gap）是知乎**高频、高价值、强时令**的提问场景：每年毕业季、考研季、秋招都是稳定的内容与流量高峰，且知乎在这个话题上沉淀了大量**第一人称的长篇经历**——这是其他平台很难替代的内容资产。

作品选这个场景，不是因为它好做，而是因为**它是知乎的主场**。

## 2.2 把沉睡的长回答，激活到「决策现场」

知乎最值钱的资产是真实经历。但这些经历今天的消费链路是：

```
想起来要搜 → 搜索 → 打开几千字的回答 → 读完 → 自己判断适不适用 → 大概率忘了
```

成本高、转化低，而且**发生在一个人「没有具体处境」的时候**——泛泛地搜「毕业该怎么选」，读到的也只能泛泛地理解。

本作把它换成：

```
你正卡在一个具体决定上 → 相关经验自动出现在旁边 → 已结构化、已标注适用边界 → 你带着它做选择
```

这是对**存量内容的再分发与再激活**：一条几年前的老回答，在一个新玩家的具体处境里重新产生价值。它不生产内容，也不替代内容，而是**改善内容被消费的时机与方式**。

具体落在两个位置，都是玩家**正在做决定**的时刻：

| 位置 | 检索什么 | 触发方式 |
|---|---|---|
| **序章 · 第 05 块**（决定方向之前） | 过来人怎么建议毕业后的选择 | **进入序章即自动加载**，不需要任何点击 |
| **每一幕的情境页**（决定具体行动之前） | 与当前具体处境相关的经验 | 一次点击展开 |

> 序章这一处的早期版本是按玩家勾选的具体路径去找「走过这条路的人」，但**真正走过同一条路的人很少**，检索命中率和相关度都差。改成「过来人怎么建议选」之后覆盖面和质量都明显变好——这是实测后的调整，不是设计预设。

## 2.3 结构化重述，把消费成本降到决策现场能承受

原文常常几千字，玩家在做决定时读不完。每张卡片压成他在那一刻真正需要的五项：

| 字段 | 作用 |
|---|---|
| **当时条件** | 作者当时的处境——先交代语境，再给结论 |
| **作者做了什么** | 具体动作，不是态度 |
| **后来发生什么** | 结果与代价 |
| **与你相似** | 为什么这条经验对你成立 |
| **与你不同** | 为什么不能照搬 |

摘要保留原文摘录，并始终附「查看原回答 / 查看原文章」的链接——**重述是入口，不是替代品**。

## 2.4 「与你不同」：对社区内容消费质量的正向贡献

这一项是刻意加的，也是整个知乎整合里我们最看重的设计。

**高赞回答被当成通用结论**，是知乎内容消费中一个真实存在的问题：一个民办本科女生的考公建议，被一个 985 男生原样套用；一个全职自媒体人的经验，被一个还要兼顾家里生意的人照搬。原作者没有错，读者也不是不认真——是**语境差异在传播过程中被丢掉了**。

这个字段强制模型写明「为什么这条经验不能直接套在你身上」。实际输出例如：

> 与你相似：刚毕业面临选择；考虑考研和考公
> **与你不同：作者是民办本科女生；有家庭经济压力**

> 与你相似：自学剪辑；刚开始时一脸懵逼
> **与你不同：作者有摄影基础；公司有短视频需求**

也就是说，作品在**提升知乎内容被正确使用的比例**，而不只是消耗内容。这是我们认为它「适配知乎社区」最实质的一点：它站在社区一侧解决问题，不是单向取用。

## 2.5 高意图的反向导流

每张卡片都带 `zhihu.com` 原文链接。玩家点击时的状态是「我正卡在这个决定上，这条经验看起来跟我有关」——这是**需求驱动的高意图点击**，不是信息流里的被动曝光。

导流发生在三处：序章的建议卡、每一幕情境页的经验卡、以及卡片底部的原文入口。

## 2.6 内容真实性与边界承诺

作品对「什么能算知乎内容」划了硬线，并且用代码和测试固定下来：

| 承诺 | 实现方式 |
|---|---|
| 知乎卡片只来自**真实检索结果** | `isZhihuUrl()` 强制 https 且域名必须是 `zhihu.com` 或其子域，否则卡片直接不成立 |
| 每张卡片必须带**作者与原文链接** | 契约里 `authorName` 与 `url` 为必填，缺一不可 |
| AI 补充内容**绝不冒充真人经验** | 检索不足时的补充卡片强制标注「**参考思路 · 非知乎内容**」，视觉样式也与知乎卡片不同 |
| 知乎内容**不会变成你的人生** | 知乎卡片与 AI 补充**都不进入 GameState**，永远不会被当成玩家的既成事实 |
| 毕业数据**不编造** | 只使用可核实来源的公开调查数字，标注年份、调查名称与来源链接；拿不到合规来源时显示「暂无已验证数据」 |

关于最后一条再补一句：序章「看看大家都在选什么」里的四个数字来自同一份**可多选**的调查，加起来超过 100%，所以我们没有把它们拼成一个看起来更漂亮的饼图。测试里专门有一条断言，防止后来的人把它改回「分布」。

## 2.7 三分钟亲自核实

我们不希望这一节只是自我陈述。可以这样验证：

1. 打开 https://indeterminate.eilnoctis.com ，点「开始我的五年」
2. **什么都不用点**，等几秒——序章第 05 块会自动出现真实的知乎回答，带作者名与原问题标题
3. 点任意一张卡片的「查看原回答」，会跳转到 zhihu.com 的原文
4. 留意卡片里的「与你不同」一项
5. 继续走到第一幕情境页，点「看看知乎朋友们是怎么选择的」，这一次检索的是与**当前处境**相关的经验
6. 如果出现标着「参考思路 · 非知乎内容」的卡片，那是检索不足时的 AI 补充——它被明确标出来了，没有伪装

# 三、技术方案

## 3.1 架构：客户端权威，后端无状态

整局 GameState 存在浏览器 `localStorage`，**状态机跑在浏览器里**。两个 API 路由只是带密钥的代理与校验器，不持有任何会话；刷新恢复靠本地存档。

```
浏览器                                     服务端（无状态）
┌───────────────────────────┐             ┌──────────────────────┐
│  GameState (localStorage) │             │  /api/v1/ai          │
│  ┌─────────────────────┐  │   候选内容    │   4 种 operation      │
│  │  Game State Engine  │◄─┼─────────────┤   提示词 + 两层规范化   │
│  │   唯一的权威          │  │             │                      │
│  └─────────────────────┘  │             │  /api/v1/zhihu/search│
│            ▲              │             │   检索 + 相关度排序     │
│            │ 只有引擎能改   │             └──────────────────────┘
│       React 界面           │
└───────────────────────────┘
```

好处是：无账号、无服务端会话、无个人数据留存；评审打开即玩，关掉即走。

| 技术 | 选择 |
|---|---|
| 框架 | Next.js 16（App Router）、React 19、TypeScript |
| 校验 | zod v4，六类领域契约 |
| 依赖 | **无 CSS 框架、无动画库、无状态管理库** |
| 部署 | Vercel + 自定义域名，中国大陆可直连 |

## 3.2 AI 只提供候选内容，状态机才能改变权威状态

这是架构上最重要的一条。模型输出要穿过三道：

1. **宽松 schema 接住**——容忍模型的格式波动，不因为一个字段名不对就整体失败
2. **规范化**——补 ID、时间戳、因果证据，裁剪超长字段，归一化枚举别名
3. **严格领域 schema 做最终闸门**——过不了就**拒绝写入**，界面提示可重试

因果完整性也在这一层校验：每条既成事实必须声明**由哪个决定引起**、**依赖哪些更早的事实**。这是回溯能够成立的前提。

## 3.3 回溯是怎么做对的

回溯最容易做错的地方是：**回到第 8 天时，第 7 个月和第 4 年发生的事必须不存在，而不是被忽略。**

做法是**每一次决定被记录时，同时保存一份决策前快照**——当时的打算 + 当时已经发生的全部事实。三次决定，三份快照，与决定一一对应：

| 回到 | 快照里的既成事实 |
|---|---|
| 第 8 天 | 0 条 |
| 第 7 个月 | 1 条（第一幕的结果） |
| 第 4 年 | 2 条（前两幕的结果） |

快照由程序从权威状态**确定性地构建，不经过 AI**。引擎会校验它确实对应那一次决定、事实列表确实等于决策前的状态，对不上**直接拒绝写入**；快照数组一旦启用就必须每次都有，否则会与决定错位、回溯会还原错误的一轮。这些都有测试覆盖。

## 3.4 知乎检索与相关度排序

- 从玩家的打算中抽取关键词（`intentKeywords()` + 领域词表），构造检索式
- 对返回结果做相关度筛选：**文本完全不命中任何关键词的结果会被丢弃**，宁可少给也不给不相关的
- 由模型对每条候选给出 0–10 的契合度，并生成 2.3 的五项结构化字段
- 排序综合契合度、赞同数与作者权重

## 3.5 失败与降级

作品在评审环境里必须一直可玩，所以每条链路都有兜底：

| 情况 | 行为 |
|---|---|
| AI 不可用 / 超时 / 额度耗尽 | 四类操作各有保守模板兜底，界面**如实标注**「保守模板（AI 暂不可用）」，不假装正常 |
| 模型返回不合法内容 | 严格 schema 拦下，拒绝写入状态，可重试 |
| 知乎检索失败或无结果 | **不阻塞主流程**：序章给出重试入口，情境页直接隐藏面板，主线照常推进 |
| 中途刷新 | 从 localStorage 恢复已提交的进度 |
| localStorage 不可用 | 回退到内存存储，当局仍可玩完 |
| 旧存档缺少新字段 | 带默认值读取，不丢档 |

## 3.6 工程质量与安全

- **228 个自动化测试**（18 个测试文件），覆盖状态机不变式、AI 规范化、知乎卡片真实性、回溯快照对齐、旧存档兼容
- GitHub Actions CI：Node 20.9 / 24 双版本跑 lint、typecheck、test、build
- 所有密钥只在服务端 Route Handler 读取，**没有 `NEXT_PUBLIC_` 前缀，不进客户端产物**，并有自动化扫描持续验证
- 服务端日志只记录操作名、次数与耗时，不含提示词与密钥
